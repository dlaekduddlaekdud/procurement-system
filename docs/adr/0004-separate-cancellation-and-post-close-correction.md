# ADR 0004: 마감 전 문서 취소와 마감 후 원장 정정을 분리한다

- 상태: 수락
- 결정일: 2026-09-03

## 배경

입고와 송장의 오류를 정정할 때 원본 문서와 원장을 직접 수정하면 이미 수행한 대사와 마감 결과를 재현하기 어렵다. 특히 마감된 기간의 원장을 과거 날짜로 변경하면 확정된 스냅샷과 현재 원장이 서로 달라진다.

마감 전 오류와 마감 후 오류는 필요한 통제 수준도 다르다. 열린 기간의 문서 취소는 해당 문서 담당자가 처리할 수 있지만, 닫힌 기간의 회계 정정은 관리자 권한과 새로운 열린 기간의 전기일이 필요하다.

## 결정

원본 문서와 원장은 수정하거나 삭제하지 않고 반대 금액의 새 원장 행을 추가한다.

- 열린 기간의 입고·송장 취소는 문서 상태를 `CANCELLED`로 바꾸고 `CANCEL_OFFSET`을 생성한다.
- 원본 문서의 기간과 취소 원장의 기간이 모두 열려 있어야 일반 취소할 수 있다.
- 마감된 원장의 정정은 문서 취소가 아니라 관리자 전용 `REVERSAL`로 처리한다.
- `REVERSAL`은 원본 기간이 닫혀 있고 새 전기일의 기간이 열려 있을 때만 생성한다.
- 정상 금액은 역분개 행을 기준으로 `CORRECTION`으로 재기표한다.
- `reversal_of_id`와 `reposting_of_id` 고유 제약으로 원본별 역분개와 역분개별 재기표를 한 번만 허용한다.
- 취소·역분개·재기표의 실행자와 사유는 append-only `audit_log`에 기록한다.

## 고려한 대안

### 대안 1: 원본 문서와 원장 금액을 직접 수정

구현은 단순하지만 과거에 어떤 값이 확정되었고 누가 변경했는지 알 수 없다. 마감 스냅샷과 현재 원장의 불일치도 설명할 수 없으므로 선택하지 않았다.

### 대안 2: 마감 여부와 관계없이 모두 문서 취소로 처리

API는 하나로 줄지만 닫힌 기간의 회계 결과가 일반 업무 권한으로 변경된다. 마감 이후에는 문서 상태보다 원장 정정 이력을 명시적으로 남겨야 하므로 분리했다.

### 대안 3: 기존 원장에 취소 여부 컬럼만 추가

유효 원장 조회는 쉬워지지만 금액 변화가 별도 거래로 남지 않는다. 잔액을 원장 행의 합으로 재현할 수 있도록 반대 금액 행을 추가한다.

### 대안 4: 중복 여부를 서비스 조회로만 확인

동시 요청 두 건이 조회를 함께 통과할 수 있다. 원장 행 잠금과 DB 고유 제약을 함께 사용해 최종 무결성을 보장한다.

## 결과

- 원본과 정정 행을 따라가며 변경 전후 금액을 재현할 수 있다.
- 마감 전 업무 취소와 마감 후 회계 정정의 권한과 기간 규칙이 분명해진다.
- 취소된 입고와 송장은 누적 수량 및 3-way matching에서 제외된다.
- 원장 유형과 연결 컬럼이 늘어나며, 유형별 필수 연결 관계를 DB CHECK 제약과 애플리케이션 코드에서 함께 유지해야 한다.

## 검증 결과

- `GoodsReceiptServiceTest`에서 입고 취소 상쇄, 발주 상태 복원, 연결 송장 수량 보호를 검증한다.
- `InvoiceServiceTest`에서 송장 취소 상쇄와 대사 재계산을 검증한다.
- `LedgerCorrectionServiceTest`에서 마감 후 역분개, 권한, 기간, 중복 방지와 재기표를 검증한다.
- `GoodsReceiptApiTest`, `InvoiceApiTest`, `LedgerCorrectionApiTest`에서 인증·요청 검증·일관된 API 응답을 검증한다.
- `AuditLogMigrationTest`와 각 서비스 테스트에서 감사 로그 스키마와 사건 기록을 검증한다.
